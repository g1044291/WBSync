# 工数管理

## 概要

タスクの見積工数・予定工数に対して日々の作業実績（[work_logs](../tables/work_logs.md)）を記録し、残工数と工数ベースの前倒し／遅れを可視化する。画面仕様は[工数管理画面](../screens/effort-management.md)を参照。

## 実績の記録

* 実績は日ごと・タスクごとに分単位で記録する
* 同一タスクに対して同一日に複数件の実績を記録できる（担当者が途中で変わった場合などを考慮）
* 実績記録時の担当者は、記録時点のタスクの担当者をデフォルト値とするが、変更可能（過去の担当者変更を実績側に反映するため）

## 人日換算

* 実績（人日）表示は `work_logs.minutes` の合計を **1人日 = 480分（8時間）固定** で換算する（`合計分 ÷ 480`）
* 担当者ごとの稼働時間設定は行わない（将来的な拡張候補）
* 人日（見積工数・予定工数・実績・残工数を含む）の表示は小数第4位まで（実運用上の最小実績入力単位30分 = 0.0625人日を丸めずに表示するため）

## 残工数

* 残工数 = 予定工数（`planned_work_days`） − 実績（人日）
* 残工数がマイナス（実績が予定工数を超過）の場合、赤字で表示する
* 予定工数が未設定（かつ集計対象の子孫タスクもない）の場合、残工数は算出せず「-」表示する

## 前倒し/遅れ（工数ベース）

タスクの実績（人日）と予定工数（`planned_work_days`）の差から、前倒し／遅れを算出する。

* 前倒し/遅れ工数 = 実績（人日） − 予定工数（人日）
* プラス（実績が予定工数を超過）＝**遅れ**。常に算出する
* マイナス（実績が予定工数内）＝**前倒し**。タスクのステータスが「完了」の場合のみ算出し、それ以外（未着手・進行中・保留）は 0 とする
* 上記いずれにも該当しない場合（進行中で実績が予定内、実績・予定が等しい 等）は 0
* 予定工数が未設定の場合は算出せず「-」表示する

> 進行中・未着手のタスクは、まだ工数を消化していないだけで前倒しとは言えないため、前倒しは完了後にのみ判定する。
> 稼働日ベースのスケジュール遅延（進捗率と日付から算出する方式）は廃止した。

## 親タスクの集計

子タスクを持つ親タスクの見積工数・予定工数・実績（人日）・残工数・前倒し/遅れ工数は、DBに保存せず、すべての子孫タスクから動的に集計して表示する（[tasks.md](../tables/tasks.md)の開始日・終了日集計と同じ方針）。

| 項目 | 集計方法 |
|------|---------|
| 見積工数 | 子孫タスクの見積工数の合計 |
| 予定工数 | 子孫タスクの予定工数の合計 |
| 実績（人日） | 子孫タスクの実績（人日）の合計 |
| 残工数 | 表示する予定工数 − 集計後の実績（人日） |
| 前倒し/遅れ工数 | 各子孫リーフタスクの前倒し/遅れ工数（判定条件適用後）のうち最大値（最も遅れているタスク基準）。算出可能な子孫が1つもない場合は「-」 |

### 親タスク自身に値が設定されている場合

[タスク編集モーダル](../screens/task-edit-modal.md)では親タスクでも見積工数（`work_days`）・予定工数（`planned_work_days`）・担当者（`assignee_id`）を入力できる。これらが設定されている（`null` でない）親タスクは、集計値ではなく**親タスク自身の値を優先表示**する。

* 見積工数・予定工数：自身に値がある場合はその値、未設定の場合のみ子孫タスクの合計
* 担当者：自身に `assignee_id` がある場合はその担当者名、未設定の場合は「-」
* 残工数：上記で決定した予定工数（自身の値 or 集計値） − 実績（人日）の集計値。親タスク自身に予定工数が設定されていれば、その予定工数と子孫の実績合計との差になる

親タスク自身の開始日・終了日は[工数管理画面](../screens/effort-management.md)では編集不可（子タスクから動的計算、[tasks.md](../tables/tasks.md)参照）。

## 担当者別集計（ダッシュボード）

[ダッシュボード画面](../screens/dashboard.md)で、担当者ごとに工数の予実・遅れを集計して表示する。

### 表示対象の担当者

プロジェクトに登録されている担当者（[assignees](../tables/assignees.md)）を全員表示する。実績・担当タスクの有無は問わない（実績の入れ忘れに気づけるようにするため）。

### 集計対象タスク

以下をすべて満たすリーフタスク（子タスクを持たないタスク）を対象とする。ステータス・実績の有無は問わない。

* 担当者が設定されている（現在割り当てられている担当者に対して集計する）

実績の有無で対象タスクを絞り込まないことで、担当中だが実績未記入のタスクの予定工数も予定工数合計に反映する。

### 集計項目

担当者ごとに以下を算出する。対象タスク・実績のいずれもない担当者は予定工数0・実績0・遅れ0として表示する。

| 項目 | 算出方法 |
|------|---------|
| 期間 | [集計対象タスク](#集計対象タスク)の開始日の最小値〜終了日の最大値。対象タスクがない場合は表示しない。集計期間の指定有無に関わらず算出する |
| 見積工数合計（人日） | [集計対象タスク](#集計対象タスク)の `work_days`（見積工数）の合計（未設定は0扱い） |
| 予定工数合計（人日） | [集計対象タスク](#集計対象タスク)（**現在**この担当者が割り当てられているリーフタスク）の `planned_work_days` の合計（未設定は0扱い） |
| 実績合計（人日） | この担当者自身が記録した実績ログ（[work_logs](../tables/work_logs.md)の `assignee_id`＝実績記録時点の担当者）の合計（人日換算は前述の[人日換算](#人日換算)と同じ、`合計分 ÷ 480`）。タスクの現在の担当者は問わない |
| 残工数（人日） | 予定工数合計 − 実績合計。マイナス（実績が予定を超過）は赤字で表示する |
| 前倒し/遅れ（人日） | [集計対象タスク](#集計対象タスク)のうち**予定工数が設定されたタスク**ごとの前倒し/遅れ（下記の判定条件適用後）の合計 |

ステータスは担当者行では算出しない（担当者単位で一意に定まらないため）。タスク行のみ表示する。

前倒し/遅れはタスク単位で「予定工数 − タスクの実績合計」に以下の判定条件を適用し、その合計を担当者の値とする（[担当者別タスク一覧](#担当者別タスク一覧ダッシュボード行展開)の担当タスク行の値と同じ）。

* マイナス（予定より実績が多い＝実績が予定を超過）：「遅れ」として常に算出する
* プラス（予定より実績が少ない＝前倒し）：タスクのステータスが「完了」の場合のみ「前倒し」として算出する。それ以外（未着手・進行中・保留）は 0
* 上記いずれにも該当しない場合は 0
* **予定工数が未設定のタスクは集計対象外**（予定がないため前倒し/遅れを判定できない）。対象タスクが1つもない担当者は 0

前倒しを完了時のみとするのは、[前倒し/遅れ（工数ベース）](#前倒し遅れ工数ベース)と同じ考え方（進行中は工数を消化していないだけで前倒しとは言えない）。タスク単位で判定して合計することで、担当者行を展開したときのタスク行の前倒し/遅れの合計と担当者行の値が一致する。

> 前倒し/遅れはタスクの実績合計（他の担当者が記録した分を含む）で算出するため、「予定工数合計 − 実績合計（この担当者自身の記録分）」とは一致しない場合がある。

予定工数は**現在の担当者**基準、実績は**実績記録時点の担当者**（`work_logs.assignee_id`）基準と、集計の基準が異なる点に注意。担当者削除により `assignee_id` が `NULL` になった実績は集計対象外（誰の実績としても計上しない）。

タスクの担当が変わった場合、現在の担当者と実績記録者が異なる担当者としてそれぞれ一覧に表示されうる。実績記録者側は、そのタスクを現在担当していなければ予定工数0（担当タスクが他にあれば含む）・実績のみが計上される。この扱いは[担当者別タスク一覧](#担当者別タスク一覧ダッシュボード行展開)の[実績のみ]行の考え方と揃えたもの。

### 合計行

一覧の末尾に、全担当者の見積工数合計・予定工数合計・実績合計・残工数・前倒し/遅れを合算した「合計」行と、全体の期間（最小開始日〜最大終了日）を表示する。見積工数・予定工数・実績・残工数は各担当者の値の単純合計。前倒し/遅れは各担当者の**判定条件適用後**の値の単純合計とするため、合計予定工数 − 合計実績とは一致しない場合がある（前倒しゲートで 0 に落ちたタスクや、予定工数未設定で集計対象外のタスクがあるため）。

### 集計期間の指定

ダッシュボードに集計期間（開始日・終了日）を指定でき、指定期間内に記録された実績工数のみを確認できる。

* **デフォルトは指定なし（全期間）**。この場合は上記のとおり期間・ステータス・見積工数・予定工数・実績・残工数・前倒し/遅れを表示する
* 開始日・終了日はいずれも任意。片方のみ指定した場合、指定した側だけを境界とする（もう一方は無制限）。判定は [work_logs](../tables/work_logs.md) の `date` が両端の日を含む範囲にあるか
* **期間を指定した場合の挙動**：
  * 実績は、その期間内に記録された `work_logs` のみを集計する（担当者行・合計行・展開したタスクツリーのすべて）
  * **見積工数・予定工数・残工数・前倒し/遅れは表示しない**。期間内実績のみの集計であり、予定との比較は行わないため。期間・ステータス・実績の列のみを表示する
  * 「指定期間内の実績のみを集計している」ことが分かるヘッダー表示を出す
* 実績の集計基準（`work_logs.assignee_id` ＝実績記録時点の担当者）は期間指定の有無に関わらず同じ

## 予実推移グラフ（ダッシュボード）

[ダッシュボード画面](../screens/dashboard.md)に、プロジェクト全体の予実の推移を日付を横軸・人日を縦軸とした複合グラフで表示する。集計期間の指定（[集計期間の指定](#集計期間の指定)）は反映せず、常に全期間を対象とする。

### 系列

| 系列 | 形式 | 算出方法 |
|------|------|---------|
| 日別実績 | 棒 | その日に記録された [work_logs](../tables/work_logs.md) の `minutes` 合計を人日換算（[人日換算](#人日換算)）した値。記録時点の担当者は問わない |
| 累積予定 | 線 | 各リーフタスクの予定工数（`planned_work_days`）を、開始日〜終了日の稼働日に均等配分し、日ごとに累積した値 |
| 累積実績 | 線 | 日別実績の累積。横軸の開始日から**今日**まで描画する（今日より後の日付の実績がある場合は、その最終日まで） |
| 完了予測 | 線 | 累積実績線の終端（今日）の累積実績を起点に、予測総工数へ向けて残りの予定期間で積み上げた値（[完了予測の算出](#完了予測の算出)） |

### 累積予定の配分

* 対象は、予定工数が0より大きく、開始日・終了日がともに設定された（終了日 ≧ 開始日の）**リーフタスク**。担当者の有無・ステータスは問わない
* 稼働日の判定は[稼働日判定の優先順序](holiday-settings.md)に従い、タスクの担当者の個人休日も考慮する（スケジュール計算と同じ）。期間内に稼働日が1日もない場合は開始日に全量を配分する
* 期間未設定・予定工数未設定のタスクは配分できないため累積予定に含めない。このため累積予定の最終値は、期間が設定されたリーフタスクの予定工数合計となる
* 親タスク自身に設定された予定工数は用いない（リーフタスクの値のみを積み上げる）

> 担当者別集計の合計行の予定工数は担当者が設定されたリーフタスクのみの合計のため、担当者未設定のタスクがある場合は累積予定の最終値と一致しない。

### 完了予測の算出

1. リーフタスクごとに**実績予測**（完了までに要する総工数の見込み）を算出する
   * 進捗率（`progress`）が0より大きい：実績 ÷ 進捗率（例：実績3人日・進捗率50% → 6人日）
   * 進捗率0%：実績予測を算出できないため、予定工数（未設定は0）を予測値とする。ただし既に実績が予定工数を超えている場合は実績とする
2. **予測総工数** = 全リーフタスクの実績予測の合計（累積実績の合計を下回る場合は累積実績の合計）
3. 起点（累積実績線の終端日。通常は今日）の値を累積実績の合計とし、起点の翌日〜**予定の最終終了日**（リーフタスクの終了日の最大値）の稼働日（全体休日のみ考慮）に、残り（予測総工数 − 累積実績）を均等に積み上げる。最終値は予測総工数になる
4. 起点が予定の最終終了日以降（予定期間を過ぎている）の場合は、起点の翌稼働日に予測総工数へ到達させる

予測総工数が0（予定工数も実績もない）の場合は完了予測線を描画しない。実績が予定より多いペースで進んでいるタスク（実績 ÷ 進捗率 ＞ 予定工数）がある場合、完了予測の最終値は累積予定の最終値より大きくなる。

### 横軸の範囲

* 開始日：リーフタスクの開始日・終了日の最小値と、最初の実績日のうち早い方
* 終了日：リーフタスクの開始日・終了日の最大値、最後の実績日、今日、完了予測の到達日のうち最も遅い日（実績・予測が予定期間からはみ出す場合はその日まで）
* 期間が設定されたリーフタスクも実績も1件もない場合はグラフを描画せず、その旨を表示する。描画できる系列（例：予定のみ・実績のみ）だけを描画する

## 担当者別タスク一覧（ダッシュボード行展開）

[ダッシュボード画面](../screens/dashboard.md)で担当者行を展開すると、その担当者が関わったタスクをツリー表示する。

### 対象タスクの判定

タスクの**現在の**担当者ではなく、実績ログ（[work_logs](../tables/work_logs.md)）の `assignee_id`（記録時点の担当者）を基準に、以下のいずれかを満たすリーフタスクを対象とする。

1. 現在この担当者が割り当てられているタスク（実績の有無は問わない。[担当者別集計](#担当者別集計ダッシュボード)の予定工数集計対象と同じ）
2. 現在の担当者に関わらず、この担当者自身の実績ログが1件以上記録されているタスク（担当変更後も「その人が何をしたか」を追えるようにするため）

対象リーフタスクの祖先タスクは、ツリー構造（階層・インデント）を保つために合わせて表示する（見積工数・予定工数・実績・残工数・前倒し/遅れの集計値は持たない）。ただし期間（開始日〜終了日）は子孫タスクからの動的計算値を表示する。

### 表示内容

期間（開始日〜終了日）とステータスは全リーフ行（下記 (1)(2) いずれも）で表示する。期間は祖先タスク行でも表示する（子孫からの動的計算値）。見積工数・予定工数・残工数・前倒し/遅れは下記のとおり。

| 区分 | 見積工数 | 予定工数 | 実績 | 残工数 | 前倒し/遅れ |
|------|---------|---------|------|--------|------|
| (1) 現在の担当タスク | `work_days` | `planned_work_days` | タスクの実績合計（[人日換算](#人日換算)） | 予定工数 − 実績（予定工数未設定時は「-」） | 予定工数 − 実績 に判定条件を適用（実績が予定超過＝遅れは常に算出、前倒しはステータス「完了」時のみ、他は 0）。予定工数未設定時は「-」（担当者行の集計対象外） |
| (2) 実績のみ（現在の担当ではない） | - | - | この担当者自身が記録した実績ログの合計のみ（他担当者分は含まない） | - | - |

## 担当者別稼働時間カレンダー

[担当者別稼働時間カレンダー画面](../screens/assignee-workload-calendar.md)で、担当者×日付のマトリクス形式で日々の実績を一覧表示する。タスク単位の[工数管理画面](../screens/effort-management.md)では担当者ごとの入力漏れが把握しづらいため、日付を横軸にした一覧で補う。

* 行はプロジェクトに登録された全担当者（実績の有無に関わらず表示。[担当者別集計](#担当者別集計ダッシュボード)と同様、絞り込みは行わない）
* 列は日単位の日付（ガントチャートと同様に日付を横軸に並べる）
* 各セルは、当該担当者・当該日の [work_logs](../tables/work_logs.md) の `minutes` 合計を分単位で表示する（人日換算は行わない）
* 稼働日/休日による色分けなどの強調表示は行わない（数値表示のみ）
