# スケジュール計算

## 工数と期間の考え方

* **工数（人日）** と **期間（開始日〜終了日）** は必ずしも一致しない
  * 工数：実作業量（例：3人日）
  * 期間：カレンダー上の期間（例：2週間）
  * 他プロジェクトへの配置などを考慮し、期間に余裕を持たせることができる
* 自動計算時は「工数 + 開始日 + 休日設定」を基に終了日を算出する（休日を除いた稼働日を工数分カウント）
* 開始日・終了日はいずれも手動変更可能であり、変更後の期間が工数と一致している必要はない
* タスク編集モーダルには、開始日・予定工数から終了日を再計算する「終了日を計算」ボタン、および先行タスクの終了日から開始日を再計算する「先行タスクから開始日を設定」ボタンがあり、値がずれた場合に手動で再計算できる（[task-edit-modal.md](../screens/task-edit-modal.md)参照）。いずれも後続タスクへの伝播は行わない

## 依存関係（FS）

* 依存関係はFinish-to-Start（FS）のみ対応。1タスクにつき前タスクを1つまで設定可能
* 依存タスクを設定した時点では、前タスクの終了日の翌稼働日を自動的に開始日として設定する
* 前タスクの終了日より前に開始日を設定した場合（依存関係を破る設定）は、警告を表示しつつ設定を許可する

## 再計算のルール

* タスクの変更（工数・開始日・終了日・依存関係の変更）はリアルタイムに後続タスクへ伝播する
* 後続タスクの開始日計算には前タスクの終了日のみを使用するため、タスク保存時に保存前後で終了日に変化がない場合（開始日のみの変更を含む）は、後続タスクへの伝播処理自体を行わない（無駄な再計算を省く）
* 後続タスクの開始日の計算には、前タスクの**表示上の終了日**（手動変更済みの場合はその値）を使用する
* 後続タスクが手動で開始日・終了日を変更済みであっても、再計算で上書きする
* 後続タスクの終了日は、工数からの再計算ではなく、**期間（開始日〜終了日の日数）を維持したままずらす**
  * 例：期間2日（開始日〜終了日が2日間）のタスクにおいて、前タスクの終了日が1日後ろにずれた場合、後続タスクの開始日も1日後ろにずれ、終了日は「新開始日 + 2日」となり期間2日を維持する
  * 後続タスクに開始日・終了日が未設定の場合のみ、工数（稼働日カウント）から終了日を算出する
