# 要件定義

## 1. 概要

本システムは、工数（人日）をベースにスケジュールを自動生成するWBSツールである。
依存関係・休日・手動調整を組み合わせ、現実に即したプロジェクト計画を簡易に作成・管理する。

単一ユーザー利用を前提としつつ、複数担当者を含むプロジェクト単位のWBS管理を行う。

***

## 2. コンセプト

* 工数を入力するだけでスケジュール生成
* モダンで直感的なUI（Excelライクには拘らない）
* 軽量（〜100タスク想定）
* プロジェクト単位で管理
* 全体の休日及び担当者毎の休日を設定可能
* ポータビリティを優先し、SQLite3を利用

***

## 3. 機能要件

### 3.1 プロジェクト管理

* プロジェクト一覧画面を持ち、一覧からプロジェクトを選択するとそのWBS画面へ遷移する
* プロジェクトの作成が可能
* プロジェクトの削除・複製機能は不要
* プロジェクト間の横断機能は不要
* プロジェクトが持つ属性は以下の通り
  * プロジェクト名
  * 開始日（スケジュール計算の起点となる日付）

### 3.2 タスク管理

#### タスクの属性

| 属性 | 説明 |
|------|------|
| タスク名 | 必須 |
| 担当者 | 1タスクにつき1人。プロジェクト内の担当者から選択 |
| 工数 | 人日単位。スケジュール自動計算の入力値 |
| 開始日 | 自動計算または手動入力 |
| 終了日 | 自動計算または手動入力 |
| 依存タスク | FS（Finish-to-Start）形式で1つまで設定可能 |
| ステータス | 未着手 / 進行中 / 完了 / 保留 の4択 |
| 進捗率 | 0〜100%。手動入力 |
| 備考 | 自由記述 |

#### タスクの階層構造

* タスクは無制限の階層構造（親子関係）を持てる
* 子タスクを持つ親タスクは、開始日・終了日を子タスクから自動計算する（子の最早開始日〜子の最遅終了日）
* 親タスクには工数・担当者を設定しない
* 親タスクの進捗率は手動入力

#### タスクの操作

* タスクの作成・編集・削除が可能
* タスクを削除すると、その配下の子タスクも再帰的にすべて削除される
* 削除タスクを依存タスクとして参照していた場合、その依存関係のみ削除される
* 同一階層内でのタスクの並び順を手動で変更できる（上下移動）

### 3.3 スケジュール計算

#### 工数と期間の考え方

* **工数（人日）** と **期間（開始日〜終了日）** は必ずしも一致しない
  * 工数：実作業量（例：3人日）
  * 期間：カレンダー上の期間（例：2週間）
  * 他プロジェクトへの配置などを考慮し、期間に余裕を持たせることができる
* 自動計算時は「工数 + 開始日 + 休日設定」を基に終了日を算出する（休日を除いた稼働日を工数分カウント）
* 開始日・終了日はいずれも手動変更可能であり、変更後の期間が工数と一致している必要はない

#### 依存関係（FS）

* 依存関係はFinish-to-Start（FS）のみ対応。1タスクにつき前タスクを1つまで設定可能
* 依存タスクを設定した時点では、前タスクの終了日の翌稼働日を自動的に開始日として設定する
* 前タスクの終了日より前に開始日を設定した場合（依存関係を破る設定）は、警告を表示しつつ設定を許可する

#### 再計算のルール

* タスクの変更（工数・開始日・終了日・依存関係の変更）はリアルタイムに後続タスクへ伝播する
* 後続タスクの開始日の計算には、前タスクの**表示上の終了日**（手動変更済みの場合はその値）を使用する
* 後続タスクが手動で開始日を変更済みであっても、再計算で上書きする

### 3.4 担当者管理

* 担当者はプロジェクト内で登録・管理する（アプリ全体での共有なし）
* 担当者の休日（有給・不在日など）はプロジェクト内で手動登録する
* 担当者の休日設定はプロジェクトをまたいで共有しない

### 3.5 休日設定

* **全体の休日**：土曜日・日曜日を固定の休日とし、それ以外（祝日など）は手動登録またはCSVインポートで登録する
* **担当者毎の休日**：個人の有給・不在日などをプロジェクト内で手動登録する
* スケジュール計算時は全体の休日と担当者毎の休日の両方を考慮する
* **全体休日のCSVインポート**：1列目に日付（`yyyy/MM/dd` または `yyyy-MM-dd`）を記載したCSVファイルから一括登録できる。既存データおよびCSV内の重複日付はスキップする

***

## 4. 非機能要件

### 4.1 動作環境

* **形態**：デスクトップアプリケーション（.NET MAUI Blazor Hybrid）
* **対象OS**：Windows（主要ターゲット）
* **ランタイム**：.NET 10

### 4.2 技術スタック

| 役割 | 採用技術 |
|------|----------|
| UIフレームワーク | .NET MAUI Blazor Hybrid |
| UIコンポーネント | Razor コンポーネント（C#） |
| ORM | Entity Framework Core |
| データストア | SQLite3（EF Core経由） |

### 4.3 データ管理

* **ORM**：Entity Framework Core（マイグレーション管理含む）
* **データストア**：SQLite3
* 将来的な SQL Server / MySQL への移行を考慮し、DBアクセスはすべてEF Core経由に統一する
* エクスポート・インポート・バックアップ機能は不要
* データはローカルのSQLiteファイルで完結する
